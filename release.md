# Экспорт, тестовый запуск и релиз

Раздел «Экспорт и релиз». Он разбит на группы в том порядке, в каком обычно идут: перед публикацией, файлы для лаунчеров, сервер, проверка запуском, установка, поделиться.

## Тестовый запуск

Тестовый запуск стартует сборку на вашем компьютере в отдельной папке, чтобы убедиться, что она работает, раньше, чем это сделают другие. Окно общее для сервера и клиента. Открывается кнопкой «Тестовый запуск» в шапке проекта или из раздела экспорта.

Пока вы не приняли EULA в «Настройки» → «Тестовый запуск», ничего не запустится.

### Тестовый сервер

Sborka ставит ядро загрузчика и серверные моды в свою папку, запускает сервер без окна игры и ждёт строку `Done`. Мир каждый раз создаётся заново, папка перед запуском очищается. Это быстро и не мешает работать.

### Тестовый клиент

Запускает игру офлайн (без аккаунта, ник берётся из настроек) в отдельной папке и ждёт главного меню, потом ещё 10 секунд на поздние краши. Откроется окно игры. Миры и настройки в этой папке сохраняются между запусками. Галочка «Не закрывать игру после проверки» оставляет игру открытой, чтобы поиграть; снимки по F2 попадут в галерею страницы проекта (см. ниже). Пока такой клиент открыт, второй запуск не начнётся, чтобы не стереть его файлы: сначала закройте игру.

### Что показывает окно

- **Перед стартом:** какая Java найдена и подходит ли она (иначе «а нужна N+»), память, сколько ждать, сколько модов попадёт на эту сторону и будет ли что-то скачиваться. Первый запуск скачивает Minecraft и загрузчик, это несколько минут.
- **Во время запуска:** шаги и время с начала. Шаги сервера: Java, ядро, моды, запуск. Шаги клиента: Java, игра, библиотеки, ресурсы, моды, запуск.
- **Лог** с подсветкой ошибок и предупреждений, фильтром «только ошибки» и без прокрутки вниз, пока вы читаете.
- **После падения или зависания:** краш-репорт и `logs/latest.log` разбирает анализатор; найденные причины видны в окне, с кнопками исправления и переходом к поиску виновника. «Открыть папку» открывает папку запуска.

Тестовые процессы идут с пониженным приоритетом и облегчённым JIT, чтобы компьютер оставался отзывчивым (клиент, оставленный для игры, работает как обычно). Тестовый сервер останавливается вместе с программой.

## Релиз

Кнопка «Выпустить релиз» в шапке раздела (или `Ctrl+K` → «Выпустить релиз») делает всё сразу. Нужны номер версии, канал, список изменений (подставляется с прошлого релиза, для первого выпуска пишется «Первый выпуск сборки») и папка для архивов. По умолчанию это `Загрузки/Sborka/<проект>`, она создаётся сама; «Изменить…» выбирает другую, выбор запоминается для проекта. В эту папку ложатся `.mrpack`, архив CurseForge, серверный пак, `CHANGELOG-<версия>.md` и отчёт о проверках.

Шаги по группам:

| Группа | Шаг | Что проверяет или делает |
| --- | --- | --- |
| Проверки | Проверка анализатором | Конфликты модов, зависимости, версии игры и загрузчика |
| | Синтаксис конфигов и данных | Каждый TOML, YAML и JSON читается без ошибок (ошибки TOML и YAML — ошибки, JSON — замечание: многие моды читают JSON с комментариями) |
| | Лицензии файлов внутри архивов | Авторы разрешают класть файлы в `.mrpack` |
| | Тестовый сервер | Должен дойти до `Done` |
| | Тестовый клиент | Должен дойти до главного меню, откроется окно игры |
| Файлы | Архив `.mrpack` | |
| | Архив CurseForge | |
| | Серверный пак | Серверные моды, ядро и start-скрипты в `.zip` |
| Публикация | Скриншоты на Modrinth | Новые картинки из галереи проекта |
| | Описание на Modrinth | Заменит описание проекта текстом со страницы сборки |
| | Публикация на Modrinth | Нужны токен и slug или id проекта |
| | Публикация на CurseForge | Нужны токен загрузки и числовой ID проекта |

Какие шаги выполнять, выбирается галочками и запоминается для каждого проекта вместе с **строгим режимом**.

- Шаги идут по порядку. Ошибка останавливает релиз **до создания файлов**, ничего не публикуется.
- Шаг может пройти «с замечаниями». В строгом режиме замечания тоже останавливают релиз.
- **Только проверки** прогоняет только отмеченные проверки: без снапшота, файлов и публикации.
- Если такой номер версии уже выпускался, будет предупреждение: Modrinth и CurseForge не примут дубликат.
- После каждого настоящего запуска, удачного или нет, в папку релиза пишется отчёт `CHECKS-<версия>.md`. «Скопировать отчёт» кладёт его в буфер. У каждого шага есть подробности: какие ошибки, какие файлы.
- Удачный релиз создаёт снапшот-релиз в истории.

## Файлы для лаунчеров

| Результат | Что получается |
| --- | --- |
| `.mrpack` | Для Modrinth App, Prism, ATLauncher. Моды CurseForge лягут внутрь архива (формат не принимает ссылок на них), если это не отключено в настройках. |
| `.zip` для CurseForge | `manifest.json` и `modlist.html`. Файлы не с CurseForge и ваши overrides идут в `overrides`. |
| Экземпляр Prism | Готовый экземпляр с файлами модов и метаданными Prism, чтобы он видел обновления. |
| Папка packwiz | `pack.toml` и `.pw.toml` на каждый мод, удобно хранить в git. Повторный экспорт обновляет ту же папку. «Другая папка» выбирает новую цель. |

Перед отправкой архива с чужими jar-файлами посмотрите [лицензии](#лицензии).

## Сервер

- **Серверный пак (`.zip`):** серверные моды, `server-overrides`, ядро загрузчика и start-скрипты. Готов к распаковке на хостинге.
- **Установить как сервер в папку.** То же, но сразу в папку, с настройками:
  - Java: выбор из найденных; если выбранная старше, чем нужно для Minecraft, будет предупреждение. Если Java не найдена, скрипты вызывают `java` из `PATH`.
  - Память в ГБ, по желанию флаги Aikar (G1GC).
  - Скачать ядро и создать `start.bat` / `start.sh`; по желанию сразу запустить установщик ядра (иначе он запустится при первом старте).
  - Параметры `server.properties`: описание (motd), порт, максимум игроков, дальность прорисовки, сложность (мирная, лёгкая, нормальная, сложная), режим игры (выживание, творческий, приключение), online-mode, белый список. Существующий `server.properties` целиком не перезаписывается: меняются только эти ключи.
  - Дополнительно: разрешить полёт (нужно для модов с джетпаками, иначе игроков кикает), защита спавна, дальность симуляции, сид мира.
  - **Игроки:** белый список и операторы, ники через запятую или с новой строки. Пишутся `whitelist.json` и `ops.json`; с online-mode UUID берутся у Mojang, без него считаются по нику, как это делает сервер. С белым списком включаются `white-list` и `enforce-whitelist`.
  - **Где будет работать:** `docker-compose.yml` (образ Java нужной версии, папка сервера смонтирована внутрь) и служба systemd для Linux VPS с автоперезапуском.
  - Галочка с согласием на EULA Minecraft, по ней записывается `eula=true`.
  - Ответы запоминаются для проекта (кроме Java и EULA).

В папку сервера и в серверный пак кладётся `README-SERVER.md`: версия игры и загрузчика, нужная Java, как запускать, память, порт, как ставить на панель хостинга (Pterodactyl и похожие) и на хостинг с готовыми сборками. `start.sh` берёт Java из переменной `JAVA`, иначе `java` из `PATH`, поэтому одинаково работает на Linux-хостинге и в Docker.

Моды без серверной части на сервер не попадают.

## Установка в папку лаунчера

«В папку экземпляра» копирует файлы сборки в папку экземпляра Minecraft. Старые версии обновлённых модов удаляются, выключенные переименовываются в `.disabled`. В целевой папке ведётся файл `.sborka-installed.json`, по нему программа знает, что поставила в прошлый раз.

**16Launcher.** «Подключить» копирует моды и конфигурацию в выбранную папку игры и открывает 16Launcher. Профиль и загрузчик в лаунчере должны быть настроены заранее. Файлы с тем же путём заменяются.

## Поделиться

- **Код сборки.** Короткая строка, которая помещается в сообщение и воссоздаёт список модов с теми же версиями, без конфигов. Импорт: экран проектов → импорт → «Код сборки».
- **Lock-файл** (`.sborka.lock`). Точные версии, хеши и состояние конфигов. «Сравнить» показывает отличия lock-файла от текущего проекта.
- **Список содержимого.** Markdown (со ссылками), CSV (название, источник, тип, версия, файл, теги, заметка) или JSON, для описания проекта или чата.

## Лицензии

«Проверить лицензии» показывает, какие файлы попадут внутрь каждого архива и разрешают ли это авторы.

- Мод может запрещать распространение вне CurseForge: такие моды отчёт перечисляет, чтобы вы заменили их или отказались от публикации на Modrinth.
- В `.mrpack` кладутся моды CurseForge (если это включено в настройках) и jar-файлы из overrides. В архив CurseForge кладутся моды Modrinth и внешние файлы, плюс jar из overrides. Серверный пак содержит сами файлы серверных модов. Экземпляр Prism содержит файлы всех клиентских модов. packwiz только ссылается на моды, внутрь попадают лишь jar из overrides.
- В окне публикации на Modrinth есть галочка, подтверждающая, что у вас есть разрешение авторов, если в архив попадут моды CurseForge.

## Страница проекта

«Страница сборки» готовит текст для Modrinth и CurseForge из данных проекта: требования, моды по группам, список изменений.

- **Описание:** ваш текст о сборке в Markdown встаёт под описанием из параметров. «Скрыть библиотеки» сокращает список. Есть предпросмотр.
- **Галерея:** картинки с диска или скриншоты из папки тестового клиента (F2 в игре). Можно добавить подписи и выбрать главную картинку. Картинки загружаются на Modrinth (сразу становятся публичными); слишком большой скриншот можно сжать в JPEG. «Убрать из галереи» ничего не удаляет на стороне Modrinth.
- **Обновление описания на Modrinth** заменяет текущее после подтверждения. Нужны токен Modrinth и slug или id проекта. У CurseForge нет API ни для галереи, ни для описания, поэтому для него текст копируется.

## Публикация

- **Modrinth:** «Только Modrinth» загружает новую версию без остальных шагов релиза. Sborka собирает `.mrpack` и загружает его в уже созданный проект-сборку (slug или id) с номером версии, названием, каналом (релиз, бета, альфа), списком изменений в Markdown и необязательной отметкой «рекомендуемая». Версия сразу становится публичной. Нужен персональный токен с правом создавать версии (modrinth.com → Settings → PATs). Если в истории нет релиза, программа предупредит.
- **CurseForge:** только в составе полного релиза, с токеном загрузки (curseforge.com → Settings → API tokens). Это не тот ключ API, которым ищут моды.
